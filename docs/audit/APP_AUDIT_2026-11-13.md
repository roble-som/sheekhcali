## 3. Code-quality review

- No TODO/FIXME/HACK markers, no empty callbacks; every "not yet" action shows a labelled message.
- Architecture is consistent: features by folder (data/domain/application/presentation), Riverpod providers, no codegen.
- Debug-only paths are gated (`kDebugMode`): the design-preview library, the testing-only recording and review mode.
- Manifest permissions are minimal (wake lock, foreground media service, notifications); `INTERNET` is only in the debug manifest; the app needs no network.
- No secrets in the repository. The recording is git-ignored.

## 4. Plan

1. A1–A3: route by surah, and import all 114 surahs through the existing verified importer (same source bytes, whole-file validation, per-ayah hashes, second-source cross-check), with a documented basmala display rule and rendered-position numbering tests for every surah.
2. A4: the supplied logo becomes the medallion image, launcher icons (all densities plus adaptive) and the native launch screen. The original file is not modified.
3. A5–A8: ayah bookmarks, a text-size setting, continue-reading, and an About screen. No invented content.
4. Tests, emulator journeys, audible audio check, then the APKs (debug for testing; release only as "debug-signed, not for publishing").

The status of each item after the work is in section 5.
